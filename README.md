# Микросервис голосовой почты

## Установка

1. Copy .env

```bash
cp .env.example .env
```

2. Build go

```bash
go build cmd/main.go
```

Если не уссанавливается то переключиться на другой сервер
```bash
go env -w GOPROXY=https://goproxy.cn,direct
```

3. Run docker
```bash
docker-compose up -d
```

3. Migrations

Give permissions to db for migrations
```bash
sudo chown -R devops:devops ../voicemail_data
```

```bash
~/go/bin/goose -dir migrations sqlite3 ../voicemail_data/voicemail.db up
```


## Dump
Установит на хост sqlite
```bash
sudo apt install sqlite3
```

Выполнить дамп в файл
```bash
sqlite3 ../voicemail_data/voicemail.db "VACUUM INTO '../dump_voicemail_$(date +%d_%m_%Y).db'"
```

Накатить базу из дампа файла
Если нет папки за проектом то надо создать
```bash
mkdir -p ../voicemail_data
```

```bash
sqlite3 ../voicemail_data/voicemail.db ".restore ../dump_voicemail_10_09_2026.db"
```

## Синхронизация

Забор с АТС запускается консольной командой того же бинарника.

```bash
# первый раз — забрать, но НЕ подтверждать на АТС
docker compose exec voicemail_service ./main -sync -no-ack

# обычный забор, с подтверждением
docker compose exec voicemail_service ./main -sync

# только один ящик
docker compose exec voicemail_service ./main -sync -mailbox 090
```

Если контейнер не поднят — разовым контейнером:

```bash
docker compose run --rm voicemail_service ./main -sync -no-ack
```

В конце вывода строка с итогом:

```
Забор обращений завершён saved=6 acked=5 skipped=1 failed=0
```

| Счётчик | Что значит |
|---|---|
| `saved` | легло в базу |
| `acked` | подтверждено на АТС, ушло из INBOX |
| `skipped` | сохранено, но без mp3 — намеренно не подтверждено, приедет снова |
| `failed` | не сохранено совсем, смотри строки `ERROR` выше |

**Первый запуск делать с `-no-ack`.** Подтверждение необратимо: запись уходит из
INBOX вместе с номером звонившего, а восстановить его будет неоткуда.

### Что где застряло

```bash
curl -H "Authorization: Bearer $JWT" \
  http://localhost:8081/spa/api/external-api/voicemail/health
```

`pendingAck` — сколько записей сохранено, но ещё висит в INBOX на АТС.
`lastSyncAt` — когда последний раз что-то забиралось.

## Расписание (ночной забор)

**Системный крон не нужен.** Расписание встроено в сам сервис: пока контейнер
работает, он сам просыпается в нужное время и забирает обращения. Ни `crontab`,
ни отдельного контейнера заводить не надо.

### Как включить

Одна строка в `.env` и перезапуск:

```bash
POLL_AT=03:30
docker compose restart voicemail_service
```

Несколько раз в сутки — через запятую: `POLL_AT=03:30,13:00`

### Как выключить

Оставить пустым — `POLL_AT=` — и перезапустить. Тогда работает только ручной
запуск командой выше.

Сейчас по умолчанию **выключено**, и это намеренно — почему, в следующем разделе.

### Забор по расписанию всегда подтверждает записи

У ручной команды есть `-no-ack`, у расписания такого переключателя **нет**: оно
всегда подтверждает обращения на АТС. Значит они уходят из INBOX, и старая
страница портала, которая читает живой INBOX, опустеет.

Именно поэтому `POLL_AT` держим пустым, пока фронт не переехал на новые ручки.

Режима «забирать по расписанию, но не подтверждать» нет — и не будет, он был бы
бесполезен. Без подтверждения АТС каждую ночь отдавала бы одни и те же записи:
они не уходят из INBOX, новые за ними не пролезают, и через неделю в очереди
висело бы всё подряд, а забирались бы всё те же первые двадцать.

То же касается прогона при старте контейнера — он тоже подтверждает. Пока
`POLL_AT` пустой, ни один из них не запускается вообще.

### Как проверить, включено ли

```bash
docker compose logs voicemail_service | grep -E "POLL_AT|Следующий забор"
```

Один из двух ответов:

```
WARN  POLL_AT не задан — ночной забор выключен, работает только ручной запуск
INFO  Следующий забор обращений at=2026-09-02T03:30:00+03:00
```

Во втором случае сразу видно и что включено, и когда сработает.

### Время указывается местное

`POLL_AT=03:30` — это 03:30 по Москве, потому что в `docker-compose.yml` задано
`TZ=Europe/Moscow`. Без этой строки контейнер жил бы в UTC и забор случился бы в
06:30 утра.

Проверяется по той же строке в логе: в конце должно быть `+03:00`, а не `Z`.

```
at=2026-09-02T03:30:00+03:00   ← правильно
at=2026-09-02T03:30:00Z        ← контейнер в UTC, время уехало на 3 часа
```

### Ещё один прогон — при каждом старте сервиса

Кроме расписания, забор запускается сразу при запуске контейнера. Это защита от
простой ситуации: контейнер перезапустили в 03:29, поднялся он в 03:31 — окно
пропущено, и без этого обращения ждали бы следующей ночи.

Лишний прогон безвреден: повторный забор ничего не портит и не дублирует —
уже сохранённые обращения он просто пропускает.

## Где лежат данные

```
don_stroy_mash/
  voicemail_data/                  ← том /data, соседом к папке проекта
    voicemail.db
    audio/2026/08/090-1787591171-00000001.mp3
  go_voicemail_service_document_flow/    ← только код
```

Внутри папки проекта им нельзя: они в `.gitignore`, и `git clean -xfd` стёр бы
весь архив. В `uploads` портала тоже нельзя — тот каталог nginx отдаёт статикой
без проверки прав, а это записи разговоров с гражданами.

База и файлы лежат в одной папке намеренно: строка в базе ссылается на путь к
файлу, врозь их бэкапить нельзя — восстановишь рассинхрон. Файл SQLite при этом
нельзя копировать на живую, нужен `VACUUM INTO`.

## Ручки

Публичный префикс — `/spa/api/external-api/voicemail`, весь трафик идёт через шлюз.

```text
GET   /health                  состояние, lastSyncAt, pendingAck
GET   /mailboxes               справочник ящиков для фильтра
GET   /messages                page, limit, status, mailbox, dateFrom, dateTo
GET   /messages/{id}/audio     mp3, поддерживает Range (перемотка в плеере)
GET   /messages/{id}/plays     журнал прослушиваний: кто открывал и когда
PATCH /messages/{id}           status и/или adminComment
```

Статусы: `new`, `in_progress`, `spam`, `done`.

`PATCH` и `/audio` требуют `X-User-Id` — без него 400, а не «аноним». `id` берётся
только из заголовка от шлюза; `updatedByName` в теле — имя для показа, оно ложится
в справочник `users`, а настоящая личность всегда в id.

Авторство статуса и комментария раздельное: `status_by_id`/`status_at` и
`comment_by_id`/`comment_at`. Одно поле на двоих приписывало статус тому, кто
правил только комментарий. Истории изменений нет, хранится текущее состояние.

Обращение к `/audio` пишет строку в журнал прослушиваний. Поэтому у неё
`Cache-Control: no-store`: с кэшем повторные открытия не доезжали бы до сервиса.
Запросы с `Range` не считаются — это догрузка хвоста, а не новое прослушивание.

## Порядок переключения

Страница голосовой почты в портале читает **живой INBOX** на АТС. Первый же `ack`
начнёт его вычищать, и страница опустеет. Поэтому:

1. сервис поднят, `POLL_AT` пустой, гоняем руками `-sync -no-ack` — база
   наполняется, АТС не трогается, старая страница живёт;
2. фронт переписывается на ручки выше;
3. в один день: шлюз переводится в режим прокси и включается `POLL_AT=03:30`.

Расписание и `ack` включать **последними**.

## Чего сознательно нет

История смены статусов, уведомления, ретеншн аудио (храним вечно, ~2 ГБ в год),
поиск по номеру звонившего, счётчики по статусам, `GET /messages/{id}`.
Добавляется по мере надобности, каждое — небольшая правка.
